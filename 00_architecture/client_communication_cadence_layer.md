# CLIENT COMMUNICATION CADENCE & ANTI-DUPLICATE FOLLOW-UP LAYER

**Версия:** 1.0  
**Дата:** 2026-05-26  
**Владелец:** Дмитрий Смагин  
**Применение:** Mini Audit 10K, будущие B2B-продукты

---

## 1. Цель слоя

Обеспечить системное, контролируемое, без дублей общение с потенциальными клиентами по всем каналам — от первого касания до сделки или закрытия.

**Основные принципы:**
- Один лид = один менеджер (Дмитрий) = одна цепочка касаний
- Ни одно сообщение не уходит без approval
- Максимум 1 касание в 2–3 рабочих дня (если нет ответа)
- Уважение к клиенту: не спамить, не давить
- Логировать каждое касание

---

## 2. Путь клиента (от первого касания до ответа)

```
new_lead
   │
   ▼
[Approval Gate] ← Дмитрий смотрит карточку лида
   │  APPROVED
   ▼
contacted_email_manual  (Day 0 — первое письмо)
   │
   ├── reply_received → [Обработка ответа → сделка]
   │
   ├── no_reply (Day 2–3) → [Follow-up: WhatsApp или повторное письмо]
   │
   ├── no_reply (Day 5–6) → [Звонок или ценностное письмо]
   │
   ├── no_reply (Day 9–10) → [Финальное закрытие цепочки]
   │
   └── no_reply (Day 14+) → hold_long_term или do_not_contact
```

---

## 3. Правила каналов

### Email (Яндекс Почта)
- **Приоритет:** Первый контакт в B2B
- **Когда:** Day 0 (первое касание), Day 5–6 (ценностное)
- **Ограничения:** Не более 2 писем в цикл без ответа
- **Формат:** Профессиональный, персональный, с конкретной находкой из аудита
- **Запрет:** Не отправлять без approval Дмитрия

### WhatsApp Business
- **Приоритет:** Follow-up после email без ответа
- **Когда:** Day 2–3 (если нет ответа на email)
- **Ограничения:** Только рабочий аккаунт (не личный). Только после того, как WhatsApp Business готов.
- **Формат:** Короткое, дружественное, со ссылкой на письмо
- **Запрет:** Не через личный WhatsApp. Не автоматически.

### Telegram
- **Приоритет:** Если клиент найден в Telegram (паблик-контакты)
- **Когда:** Day 3–5 (если нет ответа нигде)
- **Ограничения:** Только если контакт публичный и релевантный
- **Формат:** 1–2 строки, ссылка на письмо или предложение

### Телефон/Секретарь
- **Приоритет:** После 2+ касаний без ответа
- **Когда:** Day 5–6 или по запросу
- **Скрипт:** Представиться, спросить правильного человека, оставить контакт
- **Запрет:** Не звонить повторно в тот же день

## 4. No-Spam Guardrails

| Правило | Значение |
|---|---|
| Max касаний на лид | 4–5 за цикл |
| Минимальный интервал | 2 рабочих дня |
| Max одновременных цепочек | Без ограничений, но каждая требует approval |
| Повторная отправка письма | Только если прошло 7+ дней |
| Auto-send | ❌ ЗАПРЕЩЁН |
| Массовая рассылка | ❌ ЗАПРЕЩЕНА |
| Отправка без approval | ❌ ЗАПРЕЩЕНА |

## 5. Approval Gate

**Каждое касание проходит через Дмитрия:**

```
[Система готовит черновик]
        │
        ▼
[Approval Card → Telegram Дмитрию]
        │
   APPROVED / REJECTED / EDIT
        │
        ▼
[Отправка или доработка]
        │
        ▼
[Логирование в outreach_log]
```

**Что требует approval:**
- Каждое первое письмо
- Каждый follow-up
- Любое изменение текста шаблона
- PDF/КП

**Что можно без approval:**
- Подготовка черновиков
- Обновление статусов после ответа клиента
- Чтение входящих

## 6. Anti-Duplicate Logic

1. **Email dedupe:** Один email = один лид = одна цепочка. Если email встречается дважды — merge, не дублировать.
2. **Domain dedupe:** Один domain (zb23.ru) = одна компания. Если разные контакты с одного домена — использовать основной.
3. **Touch count:** Счётчик `touch_count` на каждом лиде. Если `touch_count >= 5` → автоматически `hold_long_term`.
4. **Next contact date:** Поле `next_contact_date` блокирует касание раньше указанной даты.
5. **do_not_contact:** Если установлен флаг — никаких касаний ни по одному каналу.

## 7. Статусы лида

| Статус | Описание |
|---|---|
| `new` | Новый лид, ещё не обработан |
| `pending_approval` | Черновик готов, ждёт approval |
| `contacted_email_manual` | Письмо отправлено вручную |
| `contacted_whatsapp` | WhatsApp отправлен |
| `contacted_telegram` | Telegram отправлен |
| `contacted_phone` | Был звонок |
| `reply_received` | Пришёл ответ |
| `follow_up_1` | Первый follow-up отправлен |
| `follow_up_2` | Второй follow-up отправлен |
| `hold_short_term` | Пауза 7–14 дней (просили перезвонить позже) |
| `hold_long_term` | Пауза 30–60 дней (не актуально сейчас) |
| `do_not_contact` | Явный отказ / blacklist |
| `deal_in_progress` | Начались переговоры о сделке |
| `deal_closed_won` | Сделка закрыта успешно |
| `deal_closed_lost` | Сделка не состоялась |

## 8. Cadence — расписание касаний

| День | Действие | Канал | Требует approval |
|---|---|---|---|
| Day 0 | Первое письмо с конкретной находкой | Email | ✅ Да |
| Day 2–3 | Follow-up если нет ответа | WhatsApp Business | ✅ Да |
| Day 5–6 | Ценностное письмо (1 конкретная проблема) | Email или телефон | ✅ Да |
| Day 9–10 | Финальное закрытие цепочки | Любой | ✅ Да |
| Day 14 | Перевод в hold_long_term | — | Авто |
| Day 30–60 | Повторный контакт (новый повод) | Email | ✅ Да |

---

## 9. Запрет auto-send

> **АБСОЛЮТНЫЙ ЗАПРЕТ:**  
> Никакой автоматической отправки без явного approval Дмитрия.  
> Система может **готовить**, **хранить**, **логировать** —  
> но **отправлять** может только человек.

Нарушение этого правила = критический инцидент безопасности.
