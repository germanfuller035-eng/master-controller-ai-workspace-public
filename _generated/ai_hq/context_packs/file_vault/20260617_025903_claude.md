# File Intake Pipeline

## Purpose

File Intake Pipeline defines how real files are safely added to Personal File Vault OS.

## Core Rule

Do not process all files at once.

Use controlled batches.

## Pipeline

```text
User selects batch
→ Cline creates batch plan
→ Safety classification
→ Index-only file records
→ Human approval
→ Optional summary / OCR / transcript
→ Dashboard review
```

## Stages Explained

### 1. User selects batch

- Dmitry chooses a small set of files (recommended 5–20 per batch).
- Files stay where they are. Nothing is moved, copied or renamed.
- Dmitry provides only: folder/path hint, rough category, rough sensitivity.

### 2. Cline creates batch plan

- Cline opens a new batch file from the intake batch template.
- Batch gets a `batch_id` (example: `INTAKE-2026-06-05-01`).
- Cline lists planned file records (placeholders only, no real content read).

### 3. Safety classification

- Each file gets a provisional sensitivity: Green / Yellow / Red / Black.
- Red and Black files are index-only by default.
- If a file looks legal / medical / military / bank / passport — mark Red, stop, ask.
- Black content (passwords, keys, tokens, seed phrases, intimate) — placeholder only.

### 4. Index-only file records

- Cline creates one file record per file using `tpl_file_record.md`.
- `access_level: index_only`
- `can_use_for_reasoning: false`
- `can_send_to_user:

# File Vault Operating Protocol

## Role

Personal File Vault OS is the indexing and access-control layer for documents, audio, video, photos, scans and archives.

## External Storage

Recommended external root:

`D:\AI_FILE_VAULT`

Large files must stay outside Obsidian.

## Obsidian Index

Canonical index folder:

`20_file_vault_index`

It stores:

- file records;
- metadata;
- summaries;
- transcript pointers;
- OCR pointers;
- access rules;
- file request logs.

## Workflow

1. File exists in external storage.
2. Cline creates file record in `20_file_vault_index`.
3. File gets type/category/sensitivity/access level.
4. If safe, summary/transcript/OCR can be added.
5. Agent searches index, not random folders.
6. Sending any file requires approval.

## Search Logic

Agent should search:

- file records;
- summaries;
- transcripts;
- OCR text;
- tags;
- related cases/projects.

## Approval Logic

Approval required for:

- sending files;
- using Red/Black content;
- reading sensitive documents;
- creating transcript from sensitive media;
- using file in legal/medical/military/bank reasoning.

## Forbidden

- no secrets in Obsidian;
- no raw passwords;
- no keys/tokens;
- no seed phrases;
- no uncontrolled sensitive archives;
- no sending files without approval;
- no indexing full Black content.
